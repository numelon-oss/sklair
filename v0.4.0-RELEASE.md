# Sklair 0.4.0 🪶

Sklair 0.4.0 is the largest update to the compiler so far. It adds recursive
components, props and bodies, inline Lua, runtime templates, and full-document
generation. There is also a redesigned website with documentation generated by
Sklair itself!!

## Components

- Components can use other components recursively. Dependencies contribute their
  head content, assets, and runtime-template requirements to the document
- Props are passed through component attributes. Bindings set text, attributes,
  and classes, and `sklair-if` controls conditional content.
- Components can now accept body content through a default `<slot>`.
- Component folders keep `index.html`, styles, scripts, images, and other assets
  together. Relative asset references finally are rewritten into their output namespace.

## Inline Lua

Lua finally can now run inside source documents, components, generated bodies, and
layouts.

Dynamic blocks run for each use and can read its props. Blocks marked `static`
run once when the containing definition is prepared and reuse their emitted
markup. Inline Lua can emit escaped text, trusted HTML, or component uses.

One Lua runtime is shared across a build, with separate scopes for hooks,
definitions, and component or layout instances. Inline filesystem access is
read-only; writes remain available through the appropriate build-hook phases.

## Document generation and Lua libraries

Pre-build hooks can register complete pages with `documents.render`. A generated
request supplies an output path, a full-document layout, structured props, an
HTML body, and an optional origin label for diagnostics.

Lua libraries updated/added:

- **Markdown:** parse a document, render HTML, inspect headings, links, and
  sections, and use code-block options and admonitions.
- **JSON:** preserve null values and distinguish arrays from objects, including
  empty containers.
- **JSON Schema:** compile Draft 2020-12 schemas and validate JSON or structured
  Lua values, with local reference resolution.

## Optional browser templates

Components listed in `templates` can be registered as native HTML templates and
rendered with the generated `renderTemplate` ES module. The runtime returns a
`DocumentFragment`, fills its bindings once, and accepts optional body nodes.

Ordinary components still compile entirely during the build. Pages only receive
the runtime module and template registry when they use runtime templates.

## Website and documentation

The redesigned [Sklair website](https://sklair.numelon.com) literally tells you how
to use Sklair, so no longer will the source code have to be read.

The entire website is a perfect example of a Sklair project, and, apart from the
main website, the entire documentation is generated using Sklair too using the document generation feature.

## Downloads / Releases / Distribution

Delayed all the way from back in December 2025, distribution of Sklair on things
like Homebrew, APT, and winget has finally arrived and should commence shortly after
the release of 0.4.0 on GitHub.

## More (smaller things)

- Added a nice [deployment guide](https://sklair.numelon.com/docs/sklair/deployment/)
  to easily teach people how to make Sklair sites and deploy them with GitHub Pages
   It is not limited to just GitHub however.
- Migrated to Numelon go command registry: better commands + per command help
- Implemented `serve --open` and `serve --watch=false`
- Added development server path rewriting to assist with PWA development
- Improved watching of component and layout directories outside the source tree
- Stopping the development server releases its listener and removes temporary
  output
- `sklair clean` removes the complete `.sklair` workspace, including hook caches
- Removed the unused global configuration and development-only commands

## Still deferred

Unfortunately some of these were promised earlier but they will have to be pushed back to 0.5.0 or later:

- HTTP library for hooks
- automatic resource hint generation
- HTML minification
- JavaScript obfuscation
- Reusable documentation starters
- Shared components across repositories
